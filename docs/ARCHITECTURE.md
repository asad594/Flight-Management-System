# SkyBound Architecture & Design Patterns Reference

This document provides a comprehensive technical overview of the architecture, design patterns, and operational lifecycle of the SkyBound Flight Management System.

---

## 1. Dual-Runtime Architecture Overview

The system is architected to operate under two distinct runtime environments using the same templates, assets, and database schemas:

1. **Pure-Python Standalone Engine (`server.py`)**:
   - Zero external web framework dependencies (built upon standard Python `http.server.ThreadingHTTPServer`).
   - Custom regex-driven template engine (`TemplateEngine`) and URL router (`Router`).
   - Thread-safe SQLite direct driver (`Database`).

2. **Django WSGI/ASGI Enterprise Engine (`flight_system/`)**:
   - Full Django ORM, authentication middleware, form validation, and admin interfaces.
   - Django view endpoints (`core/views.py`) invoking the same GoF domain patterns.

```
                  +-----------------------------------+
                  |         Client / Browser          |
                  +-----------------+-----------------+
                                    |
                    +---------------+---------------+
                    |                               |
           [Pure Python Engine]              [Django Engine]
              (server.py)                     (manage.py)
                    |                               |
             core/framework.py              flight_system/wsgi.py
             (Router & Templates)           (Django Middleware)
                    |                               |
           core/custom_views.py               core/views.py
                    |                               |
                    +---------------+---------------+
                                    |
                    +---------------+---------------+
                    |     Domain & GoF Patterns     |
                    |  (Singleton, Strategy,        |
                    |   Observer, Factory)          |
                    +---------------+---------------+
                                    |
                    +---------------+---------------+
                    |     SQLite Storage Layer      |
                    |         (db.sqlite3)          |
                    +-------------------------------+
```

## 2. Gang of Four (GoF) Design Patterns

### 1. Singleton Pattern (`core/singleton.py`)
- **Class**: `AppConfigManager`
- **Purpose**: Guarantees that only one configuration manager instance exists throughout the application lifecycle.
- **Implementation**: Overrides `__new__` to maintain a single static `_instance` reference, providing global access to currency settings, branding, and system defaults.

### 2. Strategy Pattern (`core/strategies.py`)
- **Classes**: `PaymentStrategy` (Abstract), `CreditCardStrategy`, `EasyPaisaStrategy`, `PayPalStrategy`, `PaymentContext`
- **Purpose**: Defines a family of interchangeable payment algorithms, encapsulating each one and making them dynamically swappable at runtime during checkout.
- **Implementation**: Decouples the reservation checkout process from concrete payment gateway drivers.

### 3. Observer Pattern (`core/observers.py`)
- **Classes**: `BookingSubject` (Publisher), `BookingObserver` (Subscriber)
- **Purpose**: Defines a one-to-many dependency between objects so that when a flight reservation event occurs, all registered observers are automatically notified and dispatched without tight coupling.
- **Implementation**: Automatically creates database notification records upon booking confirmation.

### 4. Factory Pattern (`core/factories.py`)
- **Class**: `DomainFactory`
- **Methods**: `create_user()`, `create_flight()`, `create_booking()`
- **Purpose**: Encapsulates entity instantiation and database persistence logic, providing a centralized interface for creating domain models.

## 3. Database Schema Overview

The SQLite database (`db.sqlite3`) defines 6 core relational tables:

- **`users`**: User identity, credential storage, and `is_staff` role authorization.
- **`flights`**: Flight route schedules, pricing, category ('Domestic'/'International'), and available seat inventory.
- **`bookings`**: Reservation links mapping `user_id` and `flight_id` with reservation timestamps and statuses.
- **`payments`**: Payment transaction logs tracking amounts, payment strategies, and transaction IDs.
- **`notifications`**: User alert entries generated by the observer pattern.
- **`contact_messages`**: Inquiries submitted through the contact interface.

## 4. Verification & Testing

All architectural layers are covered by unit tests located in `core/tests.py`:
- Domain model instantiation & string representations
- Singleton instance constancy & dynamic settings
- Strategy pattern payment execution
- Observer pattern event attachments
- Factory pattern entity creation & persistence
- Router regex route parsing & parameter extraction
